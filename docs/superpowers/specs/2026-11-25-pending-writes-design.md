# 送信中だけ見せる値（pending）の設計

## 目的

hypersig.ts は、サーバーが確定したデータだけを表示する。ただし、利用者自身の操作（押したお気に入りの状態、送った文面など）を、確定するまで「処理中」と分かる形で見せることは、思想に反しない（`docs/architecture.md`「確定してから表示する」の B）。これを今の命令で手書きすると、次の3つの決まりごとをアプリが守る必要があり、間違えても気づけない（widgets のお気に入りの手本で、リポジトリ自身の説明が間違っていた）。

1. 処理中と分かる見た目にする。
2. 失敗したら、押す前の値ではなく、最新の確定値に戻す。
3. 確定値が届いたら置き換える。

`call` に `pending` を足し、この3つをランタイムが守る。サーバーの結果を先回りして見せる「楽観的更新」（A）は、今までどおり行わない。

## 合格の基準

- `action.call(input, { pending: [s.favorite.set(next)] })` で、押した瞬間に値が変わり、要素に `data-hs-pending` が付く。
- 失敗したら、その Signal がランタイムの覚えている最新の確定値に戻る。送信中にほかのタブの変更が確定していれば、その値に戻る。
- 送信中に Live View から確定値が届いたら、すぐに置き換わる（保留しない）。
- widgets のお気に入りの手本が、確定値用の Signal なしで書ける。
- 確定値のない Signal を `pending` に書くと、押した時点で例外になり、Action は送られない。
- ランタイムの増分は gzip -9 で 1 KB 以下。

## 目的にしないこと

- サーバーが決める値の先回り（A）。
- Live View が描く HTML（一覧の行など）を先に見せること。
- 成功時に確定値へ戻すこと（確定値は Live View の更新で届く）。

## 設計

- **API：** `action.call(input, { pending?, onSuccess?, onError? })`。`pending` は `set` の文の一覧。`set` 以外の文を渡したら、`call` を組み立てたときに `TypeError`。型は今の `Statements` を受け、`set` だけであることは実行時に検査する（ドキュメントに書く）。
- **受け渡しの形：** `["call", url, input, onSuccess, onError, pending]`。6番目は省略できる。`isStmtNode` は、6番目があれば `set` の文の一覧であることを検査する。
- **確定値の記録：** ランタイムは、`data-hs-signals` の確定した値の組（既定値ではないもの）を読むたびに、パスごとの最新の確定値を記録する。初期の読み込みと、Live View の更新のあと、どちらでも記録する。
- **押したとき：** `pending` の各パスに確定値の記録がなければ、例外を投げて何も送らない（文の残りも実行しない）。記録があれば、値を書き、そのパスを「この送信が受け持つ」と記録してから、Action を送る。
- **確定値が届いたとき：** 今までどおりストアを上書きする（フォーカス中の `bindValue` の例外も今まで通り）。
- **失敗したとき：** `pending` の各パスについて、そのパスをまだこの送信が受け持っていれば（あとの送信に引き継がれていなければ）、最新の確定値を書く。そのあと `onError` を実行する。
- **成功したとき：** 受け持ちを外すだけで、値は変えない。Action は、その値を描き直す Topic を発行する必要がある（発行しなければ、次の更新まで送った値が残る）。
- **処理中の見た目：** 送信元の要素の `data-hs-pending` を使う（今のまま）。

## ドキュメント

- 未確定の表示の説明（`docs/architecture.md`、サイトの concepts と reference の英語版と日本語版）の冒頭に、「基本は処理中の表示で十分で、おすすめしない。ドラッグ、頻繁な切り替え、自分の文の送信のように、どうしても必要な場面でだけ使う」と書く。
- Signal の説明には、「Signal はブラウザだけで決まる状態に使う。サーバーのデータを Signal に写して書き換えるのはおすすめしない（データの持ち主が2つになる）」と書く。Signal そのものは非推奨ではない。
- 手書きの手本（2つの Signal）の説明は、`pending` を使う形に置き換える。

## テスト

- 押した瞬間の値と `data-hs-pending`、成功後に Live View の確定値で置き換わる。
- 失敗で最新の確定値に戻る（送信中に別の確定値が届いた場合を含む）。
- 同じパスに2つ重なり、先が失敗しても、あとの送信の表示を消さない。あとが失敗したら確定値に戻る。
- 確定値のないパスで例外、何も送らない。`set` 以外を `pending` に渡すと `TypeError`。`isStmtNode` が不正な6番目を拒否する。
- ブラウザテスト：widgets のお気に入りを `pending` に書き換え、既存の4本が通る。
