When a change is committed on the server, the affected parts of the page update. hypersig.ts handles updates after a save and resyncs after a dropped connection.

Run the example Why hypersig

A page can go stale at any time

The page displays data as it was when the server read it. If another write commits in the meantime, that data is already stale when it appears.

How a change reaches the page

  1. Commit changes on the server

    The server validates input and saves the data. Once the write commits, application code announces what changed.

  2. Update the affected parts

    You declare which changes each part of the page receives. The server renders HTML for those parts and the browser applies it.

  3. Resync after reconnecting

    The browser skips older updates. When it reconnects, it receives HTML rendered from the current server state.

Type checks from actions to views

Check form field names and button inputs against the server input schema. Changes share a type between publishers and subscribers, and the data loaded for a view is typed through to rendering.

Use it in an existing app

Add hypersig.ts to a Hono app. Hono handles HTTP requests, and hypersig.ts runs server actions and updates views after a change. You can run the Hono app on its own or integrate the same app into Void.
