設計の背景

ブラウザにデータが届くまでの間にも、サーバーの状態は変わります。画面がいつでも古くなりうることが、設計の出発点です。

既存のフレームワークが表示の同期をどう扱い、どんな判断がアプリ側に残るのかを見ます。そのうえで、hypersig.ts がその負担を減らすために何を引き受けるかを説明します。

  1. 同期と型に残る課題
  2. hypersig の設計

同期と型に残る課題

React 系の状態管理と更新の最適化

React は、入力フォームやエディタなど、ブラウザ内の状態に応じて表示を更新するのに向いています。サーバーのデータもブラウザで保持する構成では、たとえば注文を取り消したときに、詳細、注文一覧、件数のどれが古くなるかをアプリ側で把握する必要があります。

同期を正しく保ちながら、再取得や再描画を絞ることが難しくなります。 更新を絞るには、どの値を保持し、どの値を計算し直すかを見極め、取得、保存、描画の関係を追う必要があります。こうした判断は経験に左右されます。コーディングエージェントも、ひとつのコンポーネントを読むだけでは、別の画面が同じデータをどこで使っているかを確認できません。 React の状態と Effect の解説

Remix と rshono の操作後の更新

Remix v2 は、フォーム送信後に画面のデータを自動で取り直し、応答が前後しても古い値で上書きしないようにします。Remix 3 では、別の URL が返す HTML で画面の一部を更新できます。rshono のメモの例では、保存の応答に新しい表示のデータも含まれます。 Remix のデータ再取得 · 応答の順序 · Remix 3 の部分更新 · rshono の保存例

操作への応答だけで更新する構成では、開いたままの画面にその後の変更を知らせる仕組みが別に要ります。 たとえば、定期処理で再集計した件数を表示に反映するには、画面がその変更を知る必要があります。

htmx の部分更新と型

htmx では、サーバーが返した HTML を画面の一部に反映できます。HTML の属性に送信先や更新先を書くので、操作と更新箇所を近くで読めます。

属性に書いた送信先や更新先と、サーバーの実装が一致するかは、標準の書き方では型で確認できません。 JSX で HTML を生成することもできますが、属性に URL や要素のセレクターを文字列で書くと、その値とサーバー側の処理との対応は TypeScript には分かりません。 htmx のリクエストと更新先

TanStack Start の型とキャッシュ

TanStack Start は、URL の検索条件やルートが読み込むデータを型でつなぎます。読み込んだデータはルートのキャッシュで再利用でき、必要に応じて TanStack Query も使えます。

キャッシュを使うと、どの取得結果を再利用し、保存後に何を取り直すかはアプリ側で決めます。 注文を取り消したとき、詳細の取得結果を更新しても、検索条件ごとに保存した注文一覧や件数が更新されるとは限りません。取得の型が合っていても、どの取得結果に影響するかは注文の仕様で決まります。 ルートのデータ取得とキャッシュ · TanStack Query の保存後の再取得

hypersig の設計

hypersig.ts は、サーバーで変更が確定したことを画面更新の起点にします。画面は TypeScript の型を使える JSX で書き、操作に渡す値と、どのデータの変更を受け取るかを型付きで指定します。更新先は、サーバーがその指定から判断します。

アプリは確定した変更を通知し、フレームワークが関係する表示だけを描画して送り直します。サーバーで HTML を生成して型で操作を結びつける点は、Rust 版 hypersig から引き継いだ考え方です。 Rust 版 hypersig の設計

確定した変更から画面を更新する

hypersig.ts では、画面を開いたときに、どのデータの変更を受け取るかをサーバー側で登録します。たとえば注文の保存が確定したら、アプリのコードが注文の変更を通知します。その通知を受け取るよう登録した一覧は、最新の注文データから HTML を生成します。ブラウザは、その HTML を画面の該当部分に反映します。

同じ注文を表示している別の利用者にも、その人が画面を開いたときの登録に従って更新を送ります。定期処理も、データを保存してから同じ変更を通知できます。

通信中や切断中の表示

画面に反映する業務上の値は、サーバーで確定した結果です。たとえば保存中のフォームは入力値と送信中の表示を持てます。注文一覧に出す値は、保存後に生成された HTML が届いたときに更新します。

確定から画面に反映されるまでには通信時間があります。接続が戻ったらサーバーの最新状態を読み直します。どの変更を通知し、どの範囲を更新するかはアプリで決めます。更新する範囲を広く取れば、その分サーバーの描画処理も増えます。
