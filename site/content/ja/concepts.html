基本概念

アプリケーションの確定状態はサーバーが管理します。ブラウザは描画結果を表示し、フォーカスや編集中の入力を保持します。

サーバーでの変更

  1. Action が入力を検証し、アクセス権を確認します。
  2. アプリケーションが変更を確定し、型付き Topic を発行します。
  3. 購読している Live View の HTML をサーバーで描画します。
  4. HTML 断片を SSE で配信し、ブラウザが対象の DOM を更新します。

バックグラウンド処理も、変更の確定後に同じ Topic を発行できます。

更新境界の決め方

各 Live View に安定したキーを付け、表示に関係する Topic を購読します。独立して変わる領域は別の View に分けます。注文明細と合計を同じ版で表示する必要がある場合は、一つの View にまとめます。

最初のページ応答には HTML が含まれます。Live View のコンポーネントはサーバーで実行します。

接続の復旧

サーバーは表示する View のキーを認証済みページに紐づけます。再接続時は最新状態を読み直します。View の描画時と更新の配信前にアクセス権を確認します。
