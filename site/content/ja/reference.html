API リファレンス

サーバーで操作を処理し、変更を通知して、画面の一部を更新するための API です。

型で確認できる範囲

  • フォームやボタンからの操作 では、ボタンが送る値と action.field() に渡すフォームの項目名を入力スキーマから確認します。受信した値と処理結果はサーバーで検証します。
  • データ変更の通知 では、通知を送る側と受け取る側で同じ型を使います。どの変更を通知するかは、保存処理のコードで指定します。
  • 変更に合わせて更新する画面の一部 では、ページから渡す引数と、取得処理から描画処理に渡す値を確認します。

Hono への組み込み

Hono アプリでは createHypersig を使います。描画や通信を自分で組み合わせる場合は、実行処理を hypersig.ts/core から使えます。

createHypersig(options)
アプリの公開 URL のオリジン、ログイン状態を確認する関数、変更通知を購読先に配る仕組みを指定します。
pageKeys
省略できます。ページの登録を暗号化する鍵の配列で、各要素は 32 バイトの鍵を base64（または base64url）にした文字列です。先頭の鍵で暗号化し、すべての鍵で復号を試します。省くと起動ごとの乱数になるので、再起動をまたいだり複数のインスタンスで動かしたりするときは指定します。
onDiagnostic
省略できます。変更通知の発行、描画、ページの接続についての出来事を受け取ります。page-token-invalid は、改ざんされたトークンや、ランタイムが持たない鍵で暗号化されたトークンを知らせます。どのクライアントでも壊れたトークンを送るだけで起こせるので、1 件ごとに警報を出さないでください。page-rebuild-failed は、有効なトークンにある View のうち、登録がなくなったものや、key() が例外を投げたり無効・重複したキーを返したりしたものの名前を view で知らせます。どちらも reset でページを取得し直します。
pageLifetimeMs
省略できます。ページの登録が有効な時間（ミリ秒）で、HTML の生成から数えます。既定は 12 時間です。接続中のストリームは期限後も続き、期限後に接続し直したときだけ reset でページを取得し直します。
hypersig.routes
操作を受け付ける URL と更新を配信する URL を、Hono のルートに追加します。サーバーで実行する処理を登録してから追加します。
hypersig.page(request, render)
リクエストを認証し、ページの HTML を生成します。

型付きリンク

Hono のルート定義から hc<typeof app>("/") を作り、 $path() が返すパスをサーバー側の JSX で href に渡せます。パスの引数名と、検証処理で定義したクエリの型をリンク生成時に確認できます。 

const links = hc<typeof app>("/");
const href = links.counters[":counterKey"].$path({
  param: { counterKey: "main" },
  query: { view: "display" },
});

カウンターの例では、受信したキーと表示モードも Valibot で検証します。 サーバー側の例 · Hono の型付きパス

フォームやボタンからの操作

フォーム送信などで実行するサーバー上の処理を Action と呼びます。

hypersig.action(name, definition) で登録します。名前は英数字、_、- からなるリテラルで書きます。Standard Schema に対応するスキーマで入力と出力を検証し、authorize で操作する権限を確認してから execute を実行します。 

<button type="button" {...increment.bind({ counterId: "main" })}>
  Increment main
</button>

action.bind(input) は送信する値をボタンに設定し、JSON で送ります。Date を含むような JSON にできない入力の型は、ここで型エラーになります。action.form() はフォームに渡す属性を返します。サーバーは処理結果を応答として返します。 

<form {...increment.form()}>
  <input type="hidden" name={increment.field("counterId")} value="main" />
  <button type="submit">Increment</button>
</form>

action.field(name) は、送信する名前が入力スキーマの最上位の項目にあるかを型で確認し、その名前を返します。入力値の検証は送信時にサーバーで行います。

ランタイムは、印を付けた要素にメッセージを書き込みます。action.fieldError(name) は、送信が失敗したときに、その項目へのスキーマのメッセージを表示するフォーム内の要素に印を付けます。errorOutlet() は Action の失敗メッセージを表示する場所で、送信したフォームの中にあるものを優先します。connectionStatusOutlet() は、ライブ更新が切れたことを伝える場所です。<p role="alert" {...errorOutlet()} /> のように要素に展開します。

action.control(name) は、項目名と、入力スキーマから読み取った制約属性（required、minLength、maxLength、pattern、min、max）を返します。<input {...add.control("title")} /> のように入力欄に展開して使います。入力スキーマが Standard JSON Schema も実装しているとき（たとえば @valibot/to-json-schema の toStandardJsonSchema() で包んだとき）だけ型に現れ、それ以外のスキーマでは型エラーになります。JSON Schema への変換は最初の呼び出しで一度だけ行います。type は出しません。変換後のスキーマに記述がない項目は、名前だけを返します。

導き出した属性によって、ブラウザがサーバーより厳しくなることはありません。サーバーが受け付ける値をはじくおそれのある属性は付けません。

  • required は、スキーマが必須とし、真偽値ではなく、空文字列をはじく項目にだけ付きます。空文字列をはじくのは、minLength が 1 以上のとき、"" に一致しない pattern があるとき、"" を含まない enum のときです。必須の v.string() は "" を受け付けるので、required は付きません。
  • pattern は、式が ^ で始まり、エスケープされていない $ で終わり、最上位に | がなく、v フラグで正規表現として解釈できるときだけ付きます。ブラウザは ^(?:pattern)$ をこのフラグで照合するためです。<textarea> では pattern は効きません。
  • min と max は、入力側のスキーマが数値のときだけ付きます。フォームの送信値は文字列なので、toNumber() や transform() で変換する項目には付きません。

変換に失敗すると、control() は Action 名を含む例外を投げます。JSON Schema にできない部分は、createHypersig に jsonSchema: { libraryOptions } を渡して飛ばせます（Valibot の v.trim() なら { ignoreActions: ["trim"] }）。飛ばしたアクションより後に書いた制約は、ブラウザでは変換前の値に対して確かめられます。飛ばすのは、後の制約の意味を変えないアクションだけにしてください。{ errorMode: "ignore" } は使わないでください。正規表現のフラグを落としてパターンだけを残すため、ブラウザが別の式で照合します。送信前に表示される文言はブラウザ標準のもので、スキーマのメッセージが表示されるのはサーバーが検証した後です。

ブラウザ側の Signal

Signal は、トグルや入力値のように、ブラウザだけで決まる状態を持ちます。signals(initial, { name }) でグループを定義します。行ごとに持つ場合は signalFamily(initial, { name }).at(key) を使います。値は JSON に限ります。式はブラウザのランタイムが評価するデータなので、eval は要らず、script-src 'self' のままで動きます。 

const editor = signals(
  { base: 0, published: 0, operation: "" },
  { name: "memo-editor" }
);
const e = editor.with({ base: draft.revision });
with(values)
そのリクエストの値で属性を描画するハンドルを返します。init() は、with に渡した項目をサーバーが確定した値として、渡さなかった項目を既定値として書きます。既定値は、ブラウザにその Signal の値がないときだけ適用されるので、Live View の更新がブラウザだけで決まる値を上書きすることはありません。with に渡した項目は、Live View の更新が届くとブラウザの値を置き換えます。
束縛
bindText(expr)、bindShow(expr)、bindAttr({ ... })、bindValue(signal) は、JSX に展開する属性を返します。サーバーが式を評価して結果を描画するので、最初の表示から正しい値になります。bindAttr に書けるのは、disabled、checked、aria-pressed、aria-expanded、aria-current、aria-hidden、aria-invalid、aria-busy、および data-hs-* 以外の data-* です。href、src、on*、style は、型でも実行時にも受け付けません。bindValue は、テキスト、数値、チェックボックスの入力欄を、string、number、boolean の Signal に結びます。hidden の入力欄にも結べるので、フォームが送信する値を Signal で決められます。ランタイムは起動時に hidden の入力欄の値を読むので、下書きから復元した値が描画した値より優先されます。
式
Signal はそのまま式です。すべてに eq と ne があります。数値には add、sub、mul、gt、ge、lt、le、真偽値には not、and、or、choose(whenTrue, whenFalse)、文字列には concat があります。値は lit(value) と uuid() で作ります。
on.click(stmts)
on.input と on.change もあります。文を順に実行します。使える文は、signal.set(expr)、真偽値の signal.toggle()、draftRef.focus()、action.call(input) です。const draftRef = ref({ name }) で ref を作り、{...draftRef.attr()} を付けた要素に draftRef.focus() がフォーカスを移します。
action.call(input, options)
文の中から Action を送ります。入力の各項目には値か式を書けます。options.onSuccess(output) と options.onError には文を書きます。action.form() も同じ二つのオプションを受け取ります。
action.pending() と action.draftRestored()
組み込みの Signal です。pending() は、その Action へのリクエストが送信中のあいだ true になります。draftRestored() は、保存した下書きがその Action の form({ draft: true }) に復元されると true になり、その Action が成功すると false に戻ります。
data-hs-pending
ランタイムは、リクエストを送ったフォームやボタンにこの属性を付け、そのコントロールが送った最後のリクエストが終わると成功でも失敗でも外します。送信中は Live View の更新でも外れません。送信中のコントロールは再び送信しません。CSS でこの属性を使うと、JavaScript なしで処理中であることを表示できます。
action.form({ onSubmit })
フォームの送信時、リクエストを送る前にブラウザで文を実行します。フォームのデータを作る前に束縛を描き直すので、Signal に束縛した hidden input は文が書いた値を送ります。ここで書いた値は、call より前の書き込みと同じく、リクエストが失敗しても残ります。リクエストが送信中のフォームは再び送信せず、文も実行しません。

画面は操作にすぐ反応し、データはサーバーが確定してから表示します。リクエストの送信中は pending() や data-hs-pending で処理中であることを示し、画面の値は確定したデータを持つ Live View の更新が届いたときに変わります。一覧の新しい行も、その更新でサーバーから届きます。TodoMVC は、完了の切り替えや削除が送信中の行を薄く表示します。 

<button
  type="button"
  aria-pressed={String(todo.completed)}
  {...toggle.bind({ todoKey: todo.key, completed: !todo.completed })}
>
  {todo.completed ? "✓" : "○"}
</button>

/* style.css */
li:has(.row [data-hs-pending]) {
  opacity: 0.55;
}

セレクタは行の .row 要素の中だけを見るので、行のポップオーバーにある編集フォームが送信中でも行は薄くなりません。

確定前の値を表示する

call より前の書き込みは通常の書き込みです。すぐに画面に出て、Action が失敗してもそのまま残ります。サーバーが確定する前に値を表示したいときは、onError で、ページを描画したときの値を書いて戻します。 

on.click([
  r.completed.toggle(),
  toggle.call(
    { todoKey: todo.key, completed: r.completed },
    { onError: [r.completed.set(todo.completed)] }
  ),
])

送信中に Live View の更新が届くと、先に表示した値を上書きします。onError はページを描画したときの値を書きます。切り替えではなく値を書くので、先に届いた Live View の更新があっても、戻す操作が別の変更になりません。ほかの人が同時に編集しうる値、サーバーが決める値 (key、順序、合計など)、検証で失敗しうる入力は先に表示せず、処理中の表示にしてください。

既知の制約

  • hypersig:action-success イベントの detail.data は、応答に data がないとき、以前の undefined ではなく null になります。

カスタム要素

地図やエディタのような JavaScript のライブラリは、カスタム要素で包みます。要素の属性とイベントは、宣言の値として一度だけ書きます。ページはその値から属性を設定してイベントを処理し、ブラウザ側のコードも同じ値で型付けされるので、どれも文字列リテラルで書きません。 

// elements.ts（サーバーとブラウザが import する）
import { customElement, event } from "hypersig.ts/element";

export const rating = customElement("star-rating", {
  attributes: { value: "number", max: "number" },
  events: { rate: event<number>() },
  ownsChildren: true,
});

// サーバー
<CustomTag
  of={rating}
  id="rating"
  {...e.bindElement(rating, { value: e.score, max: 5 })}
  {...rating.on("rate", (detail) => [
    e.score.set(detail),
    save.call({ score: detail }),
  ])}
/>
customElement(tag, { attributes, events, ownsChildren })
宣言を返します。attributes は名前ごとに "string"、"number"、"boolean"、json<T>() のどれかを指定します。events は名前ごとに event<Detail>() を指定します。T と Detail は JSON にできる型に限ります。タグ名は小文字で始め、- を含み、小文字、数字、-、.、_ だけを使います。型で検査できる部分は型が検査し、それ以外は customElement を呼んだときに検査します。属性名、イベント名、属性の種類も同じときに検査するので、打ち間違いは起動時のエラーになります。font-face や annotation-xml のように HTML が予約している名前も、同じように拒否します。属性名は小文字で、on で始まる名前（once も含みます）、style、id、data-hs-* は使えません。data-* の属性を json にすることもできません。イベント名は小文字で始め、小文字、数字、-、.、:、_ を使います。ランタイムがすべての要素で扱う click、input、change、submit は使えません。型がこれらの名前を拒否し、手書きの data-hs-on-custom にあってもランタイムは無視します。この関数と型は、Hono も React も import せず DOM のない環境でも import できる hypersig.ts/element と、hypersig.ts から export します。
<CustomTag of={declaration} />
宣言したタグ名で要素を描画します。Hono JSX が名前を持つ HTML 属性、role、part、exportparts、aria-*、data-*、children、宣言した属性（固定値）を渡せます。json の属性は、その型の JSON の値（読み取り専用の配列も含みます）を受け取り、JSON.stringify した文字列で書きます。NaN や 64 段より深い入れ子のような JSON でない値は TypeError を投げます。同じ属性を props と bindElement の両方で書くと、後に書いた方が残ります。data-hs-element-json に名前がある json の属性は、文字列を bindElement が書き終えた文字列として受け取り、それ以外の値は変換して書きます。true は空の属性として描画し、false は属性を書きません。ただし aria-*、data-*、draggable、spellcheck、contenteditable の真偽値は "true" または "false" として描画します。宣言が ownsChildren: true のときは id が必須です（なければ型エラーです）。一覧では要素ごとに別の id を付けてください。子を自分で描く要素は、タグと id が一致するときだけ Live View の更新で残り、そうでなければ作り直されて、要素の JavaScript が持っていた状態が消えます。
scope.bindElement(declaration, values)
宣言した属性を式に束縛します。サーバーが最初の値を描画し、以降はシグナルの変化に合わせてランタイムが書き込みます。属性は data-hs-element-attr に書かれ、独自の規則に従います。上の属性名の規則を満たす宣言済みの名前を受け付け、string と number は文字列として、json は JSON.stringify した文字列として、boolean は CustomTag と同じく空の属性か属性なしとして（そこに挙げた名前では "true" または "false" として）書きます。値が変わったとき（json の属性では文字列が変わったとき）だけ属性を書くので、ほかのシグナルが変わっても attributeChangedCallback は呼ばれません。id は束縛できません。子を自分で描く要素は id が変わると作り直されるので、サーバーの描画で固定の id を付けてください。bindAttr は束縛の項で説明した名前の一覧と data-hs-attr のままです。型は宣言したキーと値の型を検査しますが、余分なキーを持つ変数のオブジェクトを渡すと、そのキーも書かれます。実行時に検査するのは名前の規則だけです。
declaration.on(event, handler)
要素がそのイベントを発火したときに文を実行します。detail はイベントの detail を宣言した型の式として表します。1つの要素で複数のイベントを処理するときは、rating.on({ rate: ..., clear: ... }) のように1つのオブジェクトで渡します。2つの結果を展開すると、あとのものだけが残ります。ハンドラの中の call は、onSuccess と onError の文でも detail を使えます。同じ要素のリクエストが送信中でもこれらのイベントは実行するので、続けて起きたイベントは捨てませんが、呼び出しが重なることがあります。リスナーは要素が挿入されたあとの次の描画から付くので、connectedCallback の中で同期的に発火したイベントは何も実行しません。
ownsChildren
要素の JavaScript が子を描くときに指定します。Live View の更新は子を残し、要素の属性だけを更新します。bindElement に書いた属性は、この更新ではランタイムに任せるので、要素が attributeChangedCallback でサーバーの一時的な値を見ることはありません。サーバーが変えるつもりだった束縛済みの属性は、ランタイムが同じ tick のうちに描画し直すまで待ちます。サーバーが固定の値として描いた属性は、json も含めて通常どおり写します。要素の JavaScript はその子にユーザーの内容を描くことがあるので、ランタイムは子の中にある hypersig の属性（束縛、on.click などのハンドラ、スナップショット、値の束縛、ref、カスタムイベントのハンドラ、Action のボタン、action.form() のフォーム、エラーの出力先、下書きのフィールド）を無視します。そうしたボタンやフォームは何も送らず、フォームがブラウザの既定の送信をすることもありません。子の中で起きたイベントは、要素そのものか要素の外にあるいちばん近いハンドラが実行します。これらは要素そのものか、要素の外に付けてください。ownsChildren がない要素の JavaScript が描いた子は、次の Live View の更新で消えます。

要素を実装する: defineElement

import { defineElement } from "hypersig.ts/element";

defineElement(rating, {
  mount(host, props, emit) {
    // props: { value?: number; max?: number }
    // emit("rate", 3) は宣言で検査される
    return {
      update(props) {},
      unmount() {},
    };
  },
});
  • 宣言のタグ名で customElements.define を呼びます。同じタグが定義済みなら例外にします。
  • mount は要素が挿入されたときに呼びます。宣言した属性は種類に従って読み、属性がない、または読めないときは props に含めず、undefined として読みます。読めない場合とは、有限の数にならない number、"true" でも "false" でもない文字列の真偽値（data-*、aria-*）、JSON.parse で読めないか 64 段より深く入れ子になっている json です。number は Number() で読むので、"0x10" や "1e3" も数になり、空の文字列は数になりません。json の値は宣言した型かどうかを検査しないので、入力として扱ってください。
  • 同じタスクの中の属性の変更はまとめて、マイクロタスクで一度だけ update に届きます。宣言したすべての属性を読み直して渡します。unmount の前の変更は update に届きません。
  • unmount は要素が外されたときに呼びます。同じ要素を挿し直すと mount をもう一度呼ぶので、要素を動かすと unmount のあとに mount が走ります。
  • mount が例外を投げた要素は mount されないままで、update も unmount も呼ばれません。挿し直したときにだけ、もう一度 mount します。
  • emit(name, detail) は、バブリングしない CustomEvent を発火し、declaration.on のハンドラが受けます。

props と emit を宣言と突き合わせて検査するのは、defineElement で書いた要素だけです。自分で customElements.define に登録した要素は、宣言と突き合わせません。

React のアイランド

import { reactElement } from "hypersig.ts/react";

reactElement(sortableList, SortableList);
// SortableList: (props: { items?: Item[]; failures?: number; emit: Emit<...> }) => ReactNode

reactElement(declaration, Component) は defineElement の上に作ります。要素が挿入されると、要素に React の root を作り、宣言した属性（上の props と同じく省略可能）と emit を渡して Component を描画します。属性が変わると同じ root に描き直すので、部品の内部の状態は残ります。外されると disconnectedCallback から root を unmount します。外側の React の木が commit の最中にこの要素を外すと、React が root を描画中に unmount することを警告しますが、サーバーが描くページに外側の React の木はありません。部品の props が宣言と合わないと型エラーになり、ownsChildren: true でない宣言を渡すときも、React が子を置き換えるので型エラーになります。react と react-dom（^19）は optional の peer dependency で、hypersig.ts/react を import するアプリだけが必要とします。アイランドはサーバーで描きません。サーバーの HTML は CustomTag に渡した仮の子だけで、mount がそれを置き換えます。Shadow DOM は使わないので、ページの CSS が部品の DOM に当たります。sortable のサンプルは、ドロップした行を、確定した並びが届くまで処理中として薄く表示します。保存が失敗するとサーバーの並びに戻り（call の onError が、属性に束縛したシグナルを変えます）、処理中は新しいドラッグを受け付けず、ドラッグ中に届いた更新はドロップするまで反映を待ち、別のタブが並べ替えたあとのドロップは、画面の位置ではなくキーで適用します。

JSON の属性と Live View

Live View の render に書いた json の属性は、Topic で Live View が描き直されると変わり、その変化は update に届きます。値はページと更新の HTML に入り、Live View が描き直されるたびに全体を送るので、一覧の行数が多いときは、一覧を小さな Live View に分けて更新境界を小さくしてください。属性の大きさに上限はありません。

スクリプトの読み込み方

要素のスクリプトは自分のオリジンから配信し、<script type="module" src=...> で読み込みます。rating のサンプルがその例です。サンプルのように bun build などのバンドラで作ります。ページの script-src 'self' は、ランタイムと同じようにこのスクリプトにも適用されます。

検査できないこと

  • defineElement ではなく customElements.define で登録した要素は、宣言と突き合わせません。要素が読まない属性を設定しても何も変わらず、要素が発火しないイベントは何も実行せず、別の形の detail はそのまま文に届きます（JSON でなければ null です）。
  • json の値はブラウザで JSON.parse で読むだけで、T かどうかは検査しません。読めない値と 64 段より深く入れ子になっている値は、ないものとして扱います。
  • 変数から渡したオブジェクトにある、宣言していない bindElement のキーは、型では検査できません。
  • Live View の更新は、適用する前にサニタイズします。カスタム要素には、DOMPurify がどの要素にも許す属性、data-* と aria-*、上の名前の規則を満たすその他の属性が残ります。URL の値を検査するのは DOMPurify が許す属性だけなので、一覧にない属性には javascript: の URL のような値もそのまま残ります。要素の JavaScript は、検査せずにその値をリンクとして使わないでください。拡張した組み込み要素（is）は受け付けません。

データ変更の通知

通知の対象を表す名前とキーの組み合わせを Topic と呼びます。たとえば、カウンターという名前と、どのカウンターかを表す ID を組み合わせます。 

const changed = topic("counter", (id: string) => id);
await hypersig.publish(changed(id));

データを保存したあとで、hypersig.publish を使って変更を通知します。

変更に合わせて更新する画面の一部

関連するデータが変わったときに更新する画面の一部を Live View と呼びます。page.view(view, props) でページ内に配置します。トップレベルの page.view の props は JSON にできる値に限ります。

name
必須です。ページ内のキーになり、counter のようになります。ランタイム内で一意にする必要があり、重なると定義の時点で例外になります。英数字、_、- 以外を含むリテラルは型エラーになります。hypersig.live() で定義します。単体の live() はありません。
key
省略できます。同じ親の下に同じ定義を複数置くときに、counter.main と counter.other のように区別します。
subscribe
受け取る変更通知の対象を Topic で指定します。
authorize
現在のセッションで表示できるかを確認します。
load
表示するデータを取得します。
render
データから該当部分の HTML を生成します。

サーバーは、購読しているデータに変更があると、更新後の HTML をブラウザに送信します。
