API リファレンス

サーバーで操作を処理し、変更を通知して、画面の一部を更新するための API です。

型で確認できる範囲

  • フォームやボタンからの操作 では、ボタンが送る値と action.field() に渡すフォームの項目名を入力スキーマから確認します。受信した値と処理結果はサーバーで検証します。
  • データ変更の通知 では、通知を送る側と受け取る側で同じ型を使います。どの変更を通知するかは、保存処理のコードで指定します。
  • 変更に合わせて更新する画面の一部 では、ページから渡す引数と、取得処理から描画処理に渡す値を確認します。

Hono への組み込み

Hono アプリでは createHypersig を使います。描画や通信を自分で組み合わせる場合は、実行処理を hypersig.ts/core から使えます。

createHypersig(options)
アプリの公開 URL のオリジン、ログイン状態を確認する関数、変更通知を購読先に配る仕組みを指定します。
hypersig.routes
操作を受け付ける URL と更新を配信する URL を、Hono のルートに追加します。サーバーで実行する処理を登録してから追加します。
hypersig.page(request, render)
リクエストを認証し、ページの HTML を生成します。

型付きリンク

Hono のルート定義から hc<typeof app>("/") を作り、 $path() が返すパスをサーバー側の JSX で href に渡せます。パスの引数名と、検証処理で定義したクエリの型をリンク生成時に確認できます。 

const links = hc<typeof app>("/");
const href = links.counters[":counterKey"].$path({
  param: { counterKey: "main" },
  query: { view: "display" },
});

カウンターの例では、受信したキーと表示モードも Valibot で検証します。 サーバー側の例 · Hono の型付きパス

フォームやボタンからの操作

フォーム送信などで実行するサーバー上の処理を Action と呼びます。

hypersig.action(name, definition) で登録します。名前は英数字、_、- からなるリテラルで書きます。Standard Schema に対応するスキーマで入力と出力を検証し、authorize で操作する権限を確認してから execute を実行します。 

<button type="button" {...increment.bind({ counterId: "main" })}>
  Increment main
</button>

action.bind(input) は送信する値をボタンに設定し、JSON で送ります。Date を含むような JSON にできない入力の型は、ここで型エラーになります。action.form() はフォームに渡す属性を返します。サーバーは処理結果を応答として返します。 

<form {...increment.form()}>
  <input type="hidden" name={increment.field("counterId")} value="main" />
  <button type="submit">Increment</button>
</form>

action.field(name) は、送信する名前が入力スキーマの最上位の項目にあるかを型で確認し、その名前を返します。入力値の検証は送信時にサーバーで行います。

ブラウザ側の Signal

Signal は、トグルや入力値のように、ブラウザだけで決まる状態を持ちます。signals(initial, { name }) でグループを定義します。行ごとに持つ場合は signalFamily(initial, { name }).at(key) を使います。値は JSON に限ります。式はブラウザのランタイムが評価するデータなので、eval は要らず、script-src 'self' のままで動きます。 

const editor = signals(
  { base: 0, published: 0, operation: "" },
  { name: "memo-editor" }
);
const e = editor.with({ base: draft.revision });
with(values)
そのリクエストの値で属性を描画するハンドルを返します。init() は、with に渡した項目をサーバーが確定した値として、渡さなかった項目を既定値として書きます。既定値は、ブラウザにその Signal の値がないときだけ適用されるので、Live View の更新がブラウザだけで決まる値を上書きすることはありません。with に渡した項目は、Live View の更新が届くとブラウザの値を置き換えます。
束縛
bindText(expr)、bindShow(expr)、bindAttr({ ... })、bindValue(signal) は、JSX に展開する属性を返します。サーバーが式を評価して結果を描画するので、最初の表示から正しい値になります。bindAttr に書けるのは、disabled、checked、aria-pressed、aria-expanded、aria-current、aria-hidden、aria-invalid、aria-busy、および data-hs-* 以外の data-* です。href、src、on*、style は、型でも実行時にも受け付けません。bindValue は、テキスト、数値、チェックボックスの入力欄を、string、number、boolean の Signal に結びます。hidden の入力欄にも結べるので、フォームが送信する値を Signal で決められます。ランタイムは起動時に hidden の入力欄の値を読むので、下書きから復元した値が描画した値より優先されます。
式
Signal はそのまま式です。すべてに eq と ne があります。数値には add、sub、mul、gt、ge、lt、le、真偽値には not、and、or、choose(whenTrue, whenFalse)、文字列には concat があります。値は lit(value) と uuid() で作ります。
on.click(stmts)
on.input と on.change もあります。文を順に実行します。使える文は、signal.set(expr)、真偽値の signal.toggle()、draftRef.focus()、action.call(input) です。const draftRef = ref({ name }) で ref を作り、{...draftRef.attr()} を付けた要素に draftRef.focus() がフォーカスを移します。
action.call(input, options)
文の中から Action を送ります。入力の各項目には値か式を書けます。同じハンドラーで call より前に書いた変更は、すぐに画面に出ます。Action が失敗し、その後に Live View がそのパスの値を書いていなければ、ランタイムは元の値に戻します。送信中に Live View からそのパスの値が届いた場合は、送信が終わるまで適用を待ちます。options.onSuccess(output) と options.onError には文を書きます。action.form() も同じ二つのオプションを受け取ります。
action.pending() と action.draftRestored()
組み込みの Signal です。pending() は、その Action へのリクエストが送信中のあいだ true になります。draftRestored() は、保存した下書きがその Action の form({ draft: true }) に復元されると true になり、その Action が成功すると false に戻ります。
action.form({ onSubmit })
フォームの送信時、リクエストを送る前にブラウザで文を実行します。ここで書いた値は、call より前の書き込みと同じく、その送信リクエストが持ちます。onSubmit を持つフォームは、前のリクエストが送信中でも再び送信できます。それぞれのリクエストが自分の書き込みと仮の行を持ち、pending() とフォームの data-hs-pending 属性は最後のリクエストが終わるまで残ります。onSubmit のないフォームは一度に一つのリクエストだけを送り、送信中にもう一度送信しても無視します。
insertTemplate(initial, { name })
楽観的な一覧への挿入に使う行のテンプレートを定義します。ID name-番号 は呼び出したときに割り当てられるので、モジュールの直下で定義します。initial で項目の型を決め、item.項目名 は挿入する行のその項目を表す式です。部品は次のとおりです。
  • template() は <template> 要素に付けます。中身のルート要素はちょうど一つにし、すべての Live View の外に置きます。DOMPurify が Fragment 内の <template> を取り除くためです。束縛 (bindText、bindShow、bindAttr) は、サーバーでは initial の値で、ブラウザでは挿入した値で item を描画します。item はテンプレートの中のこれらの束縛でだけ使ってください。ほかの場所で使っても誤りは報告されず、サーバーでは別のスコープの束縛が false と描画し、ブラウザでは仮の行の外で値を持ちません。
  • slot() は、ブラウザが行を挿入する一覧の要素に付けます。確定した行を描く Live View の中の、項目が加わる一覧にだけ置いてください。スロットの Live View に確定した行が届かない場合や、スロットがどの Live View の中にもない場合、成功した仮の行はページを読み込み直すまで残ります。
  • insert(values, key) は文です。そのテンプレートのすべてのスロットの末尾に仮の行を足します。値はリテラルか式、key は文字列か文字列の式です。項目名の誤りは型でだけ検査するので、型のない呼び出し元は、未知の項目名を書いてもエラーになりません。
  • confirms(key) は確定した行に付けます。スロットを含む Live View のどこかに (入れ子の Live View の中は除く) confirms(key) を持つ要素が現れると、その key の仮の行を取り除きます。Action が失敗したときも取り除きます。 
<button
  type="button"
  {...r.bindAttr({ "aria-pressed": r.completed })}
  {...on.click([
    r.completed.toggle(),
    toggle.call({ todoKey: todo.key, completed: r.completed }),
  ])}
>
  <span {...r.bindText(r.completed.choose("✓", "○"))} />
</button>

楽観的な追加は、これらをつなげて作ります。ブラウザが key を作り、仮の行を表示し、Action の入力で key を送ります。サーバーは key の形式を検証し、すでにある key は拒否し、確定した行を confirms(key) 付きで描画します。ブラウザは送信のたびに key を書き換えるので、hidden input にサーバーが描く値は JavaScript なしで送るフォームのためだけにあります。リクエストごとに新しい key を描いてください。そうしないと、ネイティブの送信が key の検証で失敗します。 

const newTodo = insertTemplate({ title: "" }, { name: "new-todo" });
const composer = signals({ title: "", key: "" }, { name: "composer" });
const entry = composer.with({ key: crypto.randomUUID() });

<form
  {...entry.init()}
  {...add.form({
    resetOnSuccess: true,
    onSubmit: [
      entry.key.set(uuid()),
      newTodo.insert({ title: entry.title }, entry.key),
    ],
  })}
>
  <input type="hidden" name={add.field("todoKey")} {...entry.bindValue(entry.key)} />
  <input name={add.field("todoTitle")} {...entry.bindValue(entry.title)} />
</form>

<ul {...newTodo.slot()}>
  {todos.map((todo) => (
    <li {...newTodo.confirms(todo.key)}>...</li>
  ))}
</ul>

<template {...newTodo.template()}>
  <li><span {...newTodo.bindText(newTodo.item.title)} /></li>
</template>

確定した一覧は Live View が持ち、ブラウザが描くのは仮の行だけです。Live View を morph するあいだ、仮の行はいったん外し、morph のあとでスロットの末尾に付け直します。morph でスロットがなくなった仮の行は捨てます。仮の行の中にあるフォーカスは、morph で失われます。Action が失敗すると仮の行を取り除きます。仮の行の並べ替えと編集はできません。

削除に新しい API は要りません。行の Signal に removed 項目を持たせ、bindShow(r.removed.not()) で隠し、call より前に立てます。 on.click([r.removed.set(true), remove.call({ todoKey: todo.key })])。呼び出しが失敗すると、removed が元に戻って行が再び表示されます。

既知の制約

  • 楽観的な表示が一瞬戻ることがあります。送信中に、commit 前の値を持つ Live View の更新が届き、次に応答が届き、そのあとに commit 後の更新が届く順序のときです。
  • 同じパスに対する別々のコントロールからの呼び出しが重なると、片方が失敗したときに、もう一方の呼び出しの楽観的な値に戻ることがあります。次の Live View の更新で直ります。
  • hypersig:action-success イベントの detail.data は、応答に data がないとき、以前の undefined ではなく null になります。

データ変更の通知

通知の対象を表す名前とキーの組み合わせを Topic と呼びます。たとえば、カウンターという名前と、どのカウンターかを表す ID を組み合わせます。 

const changed = topic("counter", (id: string) => id);
await hypersig.publish(changed(id));

データを保存したあとで、hypersig.publish を使って変更を通知します。

変更に合わせて更新する画面の一部

関連するデータが変わったときに更新する画面の一部を Live View と呼びます。page.view(view, props) でページ内に配置します。

name
省略できます。ページ内のキーの先頭になり、counter-1 のようになります。ランタイムが定義ごとに番号を付けるので、別々の定義のキーが重なることはありません。英数字、_、- 以外を含むリテラルは型エラーになります。
key
省略できます。同じ親の下に同じ定義を複数置くときに、counter-1.main と counter-1.other のように区別します。
subscribe
受け取る変更通知の対象を Topic で指定します。
authorize
現在のセッションで表示できるかを確認します。
load
表示するデータを取得します。
render
データから該当部分の HTML を生成します。

サーバーは、購読しているデータに変更があると、更新後の HTML をブラウザに送信します。
